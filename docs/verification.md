# Проверка MVP — 2026-09-27

## Сборка

- Windows 11 x64, локальный .NET SDK 10.0.401.
- Release solution: 0 ошибок, 0 предупреждений.
- Framework-dependent publish win-x64: успешно, без сторонних пакетов и без встроенного runtime.
- Установленный системный .NET Desktop Runtime: 10.0.11.
- При тестах в sandbox активация COM блокировалась с E_ACCESSDENIED. Повторная диагностика в обычном пользовательском контексте прошла; приложению не нужны права администратора.

## Реальный Windows API

Обнаружены два подключённых монитора:

| Экран | Разрешение | Ориентация | Координаты |
|---|---|---|---|
| 1 | 2560×1440 | Горизонтальная | 0, 0 |
| 2 | 2160×3840 | Вертикальная | 2560, −1346 |

Диагностический `--diagnose` завершился с кодом 0, вернул два разных device path и текущие пути обоев.

Интеграционный тест `WallpaperLight.Checks --apply-copy ...` выполнен после явного разрешения пользователя:

- Список не пуст, device ID уникальны и не пусты, размеры положительны.
- Копия существующего изображения назначена первому монитору.
- API вернул новый путь для первого монитора.
- Путь второго монитора остался неизменным.
- Исходный путь восстановлен в `finally`; повторное чтение подтвердило восстановление обоих исходных путей.

## UI

- Приложение запущено через Computer Use, карточки обоих мониторов отображаются.
- Русская локализация автоматически выбрана по системному языку.
- Проверено открытие стандартного диалога выбора и его отмена.
- Окно также наблюдалось на вертикальном 4K-мониторе с системным масштабом 150%; обе карточки и кнопки доступны.
- Полный сценарий назначения через диалог не подтверждён: инструмент UI-автоматизации возвращал устаревшие индексы элементов модального окна. Вместо этого проверен реальный метод сервиса интеграционным тестом выше.
- Автоматический перенос окна между мониторами не выполнен: инструмент запрещает конечную точку drag за пределами окна. Физическое переподключение монитора, масштабы 125/175/200% и минимальное окно с прокруткой требуют отдельной ручной проверки.

## Предварительное потребление ресурсов

Release без отладчика, открытое окно, после COM/UI-проверок, Windows UI automation была подключена. Tray и slideshow в MVP отсутствуют.

- Working Set: 72.82 MiB.
- Private Bytes: 23.49 MiB.
- За 10.005 с процесс накопил 390.625 мс CPU — около 3.9% одного логического процессора, или 0.24% суммарной мощности 16 логических процессоров.

Это диагностический замер в тестовой среде, не подтверждение чистого idle около 0%. Потребление без UI automation и в tray нужно измерить отдельно на следующем этапе. GC/working-set trimming не применялись.
