# Wallpaper Light

Лёгкий менеджер обоев для нескольких мониторов Windows 11. C# / .NET 10 / WinForms, без сторонних runtime-библиотек, WebView, служб и сетевых запросов приложения.

[Скачать готовую автономную версию](https://github.com/EugenAiDev/WallpaperLight/releases/latest) · [Проверки сборки](https://github.com/EugenAiDev/WallpaperLight/actions/workflows/build.yml)

Для запуска распакуйте весь ZIP и откройте `WallpaperLight.exe`. Устанавливать .NET не требуется.

## Текущее состояние — папки, циклы, трей и автозапуск

- Обнаружение подключённых мониторов через `IDesktopWallpaper`.
- Отдельная карточка: Windows device path, разрешение, ориентация, координаты и текущие обои.
- Ручное назначение JPG, JPEG, PNG или BMP выбранному монитору.
- Обновление списка после `WM_DISPLAYCHANGE` с задержкой 500 мс для объединения событий; постоянного опроса нет.
- PerMonitorV2, прокрутка карточек, системный шрифт.
- Русский интерфейс при русском языке Windows, английский для остальных языков.
- Две общие папки для горизонтальных и вертикальных изображений; монитор выбирает папку по ориентации.
- По порядку или случайные полные циклы без повторов; Next, Previous, Random, «Сменить все».
- Отдельная история до 50 изображений для каждого монитора и ориентации.
- Настройки рядом с exe, атомарная запись, резервная копия и восстановление повреждённого JSON.
- Выбор языка «Как в системе / Русский / English» в настройках.
- Светлая, тёмная и системная тема с переключением без перезапуска; системная тема по умолчанию.
- Название модели из EDID (при доступности), обозначение дисплея, основной монитор, разрешение, ориентация и координаты.
- Собственная иконка приложения и трея с размерами 16–256 px. Воспроизводимый генератор: `tools/New-AppIcon.ps1`.

Кнопка X скрывает окно в трей. Двойной щелчок по значку или повторный запуск EXE открывает существующее окно. Меню трея содержит смену обоев для всех/отдельных мониторов и «Выход» для полного завершения. Завершение сеанса Windows не блокируется.

В настройках доступны «Запускать с Windows (при входе в систему)» и «Запускать свёрнутой в трей». Обе опции по умолчанию выключены. Автозапуск использует запись `WallpaperLight` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`; администратор не нужен. После переноса portable-папки включите автозапуск из нового расположения. Состояние автозапуска читается из реестра, а скрытый запуск хранится как `startMinimized` в JSON. При запуске программа не изменяет обои и положение изображения. Таймер смены пока не реализован.

## Requirements

- Windows 11 x64, обычный расширенный рабочий стол.
- Для сборки: .NET SDK 10.
- Для запуска framework-dependent версии: .NET Desktop Runtime 10 x64.
- Администратор не нужен.

## Build

Из корня репозитория:

```powershell
dotnet build WallpaperLight.slnx -c Release
```

Если SDK установлен локально в проект, вместо `dotnet` используйте `.\.dotnet\dotnet.exe`.

## Run

```powershell
.\WallpaperLight\bin\Release\net10.0-windows\WallpaperLight.exe
```

Откройте «Настройки» и один раз укажите две папки — горизонтальную и вертикальную. Каждый монитор автоматически использует нужную. Подпапки, скрытые и системные файлы исключены. Папки не сортируют изображения по размерам: их содержимое выбирает пользователь.

«Далее» следует режиму монитора. «Случайные» использует случайный цикл независимо от выбранного режима. «Назад» возвращается по истории успешных назначений. История и очереди существуют до закрытия приложения; ручной выбор и возврат по истории допускают повтор по явному действию пользователя. При переходе на новый случайный цикл первая картинка отличается от последней предыдущего, если доступно больше одной.

«Выбрать обои…» назначает файл только соответствующему монитору и не меняет папку. «Обновить» перечитывает дисплеи и сбрасывает кэш файлов: новые или исправленные файлы будут учтены при следующей смене. Повреждённые кандидаты пропускаются до обновления. Пустая/недоступная папка не меняет текущие обои.

При смене ориентации уже подключённого монитора программа однократно применяет изображение из соответствующей общей папки. Сохранение новых папок само по себе обои не меняет. Истории/очереди изменённой ориентации сбрасываются. Другие мониторы могут показывать те же изображения — межмониторного запрета повторов нет.

Диагностика только для чтения (выход 0 — успех, 1 — ошибка):

```powershell
.\WallpaperLight\bin\Release\net10.0-windows\WallpaperLight.exe --diagnose "$PWD\monitors.json"
```

Этот JSON содержит локальные пути к изображениям и идентификаторы мониторов. Не добавляйте диагностический файл в репозиторий.

Интеграционная проверка на реальном оборудовании, по умолчанию только чтение:

```powershell
.\tests\WallpaperLight.Checks\bin\Release\net10.0-windows\WallpaperLight.Checks.exe
```

Проверки логики, настроек и изображений без изменения рабочего стола:

```powershell
.\tests\WallpaperLight.Checks\bin\Release\net10.0-windows\WallpaperLight.Checks.exe --unit
```

Для явной проверки назначения можно добавить `--apply-copy <полный-путь-к-новому.jpg>`: тест скопирует текущие обои, временно назначит копию одному монитору, проверит остальные и восстановит исходный путь в `finally`. Запускать только когда допустима краткая смена обоев; при аварийном завершении процесса восстановление не гарантируется. Копия остаётся по указанному пути. Это интеграционный исполняемый тест без NuGet-зависимостей, а не набор для `dotnet test`.

## Автономная portable-сборка

Готовый архив: `artifacts/WallpaperLight-win-x64-self-contained.zip`. Распакуйте **всю папку** и запустите `WallpaperLight.exe`. .NET включён в архив; устанавливать runtime или приложение не нужно. Выбирайте папку с правом записи, чтобы сохранять настройки рядом с EXE.

Собрать и проверить такой архив из исходников:

```powershell
./tools/Publish-Release.ps1
# Если SDK установлен локально:
./tools/Publish-Release.ps1 -Dotnet ./.dotnet/dotnet.exe
```

Нужны Windows и .NET SDK 10. При первой сборке SDK скачает runtime-пакеты с NuGet. Скрипт выполняет проверки, создаёт чистую папку сборки без личных настроек, ZIP и SHA-256. Обрезка сборок (trimming) отключена для совместимости WinForms/COM. Программа не подписана сертификатом.

GitHub Actions выполняет тот же сценарий на Windows и сохраняет архив в артефактах запуска. Готовые ZIP следует прикладывать к GitHub Releases, а не хранить в истории исходников.

## Start with Windows

Включите «Запускать с Windows» в настройках. Используется только запись текущего пользователя `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, без службы и повышения привилегий. Перед переносом portable-папки выключите автозапуск и включите его из нового расположения.

## Configuration

Настройки находятся в `data/settings.json` относительно exe, не относительно рабочего каталога процесса. Изменения сохраняются сразу после «Сохранить» и выбора режима монитора.

```json
{
  "schemaVersion": 1,
  "language": "system",
  "startMinimized": false,
  "theme": "system",
  "folders": {
    "landscape": "C:\\Wallpapers\\Horizontal",
    "portrait": "C:\\Wallpapers\\Vertical"
  },
  "monitors": {}
}
```

Пустые папки в defaults означают «не настроено». Язык: `system`, `ru` или `en`. В `monitors` сохраняются только персональные режимы по device path; папки там не дублируются. Отключённые мониторы не удаляются из настроек.

Запись идёт через временный файл и атомарную замену с одной `.bak`-копией. Повреждённый JSON копируется в `.corrupt-*.json` перед восстановлением defaults, сохраняются последние три таких копии. Новая неподдерживаемая версия схемы не перезаписывается, редактирование отключается. При отсутствии прав на запись программа показывает сообщение; переносить данные в AppData или требовать администратора не будет.

## Architecture

- `Native/DesktopWallpaperInterop.cs`: первые пять COM-методов в порядке Windows SDK, без неиспользуемой функциональности.
- `Services/WallpaperService.cs`: COM-объект на UI STA-потоке, освобождение возвращённых строк и COM-ресурса, граница `IWallpaperService` для будущих тестов бизнес-логики.
- `Services/WallpaperCatalog.cs`: общий кэш путей; только сканирование каталога выполняется вне UI-потока.
- `Services/WallpaperNavigator.cs`: независимые циклы и история, пропуск недоступных кандидатов, ограниченные попытки.
- `Services/SettingsService.cs`: JSON, проверка значений, восстановление и атомарная запись.
- `Models/MonitorInfo.cs`: данные дисплея.
- `UI/MainForm.cs`, `MonitorCard.cs`: адаптивная компоновка и ручное назначение файла.
- `Resources/Strings*.resx`: стандартные русские и английские ресурсы.

Программа передаёт путь изображения Windows и не создаёт объединённый bitmap. Перед применением декодируется только выбранный файл для проверки, затем Image и поток сразу освобождаются; сканирование папок не декодирует изображения. COM работает на UI STA-потоке. Если проверка и применение больших изображений заметно блокируют окно, модель потоков будет пересмотрена по результатам измерений.

## Known limitations

- Номера карточек — только подписи; device path используется для вызовов API и настроек. Если EDID недоступен, выводится имя устройства, предоставленное Windows.
- Windows задаёт Fill/Fit/Center/Stretch глобально для всех дисплеев. MVP сохраняет существующее положение; переключатель появится позже.
- Windows slideshow, Spotlight или DisplayFusion могут перезаписывать обои. Программа не отключает их автоматически.
- Нет гарантий для RDP, клонирования дисплеев и отдельных обоев виртуальных рабочих столов.
- Device path может измениться после смены порта или драйвера.
- Цель 30–60 MB RAM — ориентир, а не гарантия. Измерять Working Set и Private Bytes Release-сборки без отладчика после прогрева.

## Проверка MVP

1. Собрать Release без ошибок и предупреждений.
2. Запустить диагностику и сопоставить список с подключёнными дисплеями.
3. Запустить UI; проверить карточки и отмену выбора файла.
4. Назначить файл одному монитору; убедиться, что обои второго не изменились.
5. Проверить перенос окна между дисплеями с 100% и 150%, уменьшение окна и прокрутку.
6. Отключить и подключить монитор; проверить обновление карточек.

Фактические результаты MVP зафиксированы в `docs/verification.md`, следующего этапа — в `docs/verification-stage2.md`. Логика проверяется с подменой `IWallpaperService`, файловые операции — во временных каталогах. Проверка реального COM запускается отдельно и явно.
